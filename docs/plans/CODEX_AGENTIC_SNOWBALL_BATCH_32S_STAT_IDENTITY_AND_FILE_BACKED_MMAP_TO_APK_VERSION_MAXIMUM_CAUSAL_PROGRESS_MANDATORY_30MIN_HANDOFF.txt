KNOWN INHERITED REVIEW DEBT

A. STAT IDENTITY MISMATCH

PR #94 review found that the same namespace file can receive different inode identity through two Linux interfaces:

- `fstat(open(path))` derives `st_ino` from the resolved object's canonical manifest offset;
- `newfstatat(path)` currently derives `st_ino` from the later `"path"` token offset.

This violates the expectation that the same resolved object reports one stable `(st_dev, st_ino)` identity across stat interfaces and can break applications that compare metadata to confirm file identity.

Required repair:

- establish one canonical bounded namespace object identity source;
- use it for both `fstat` and `newfstatat` when they refer to the same resolved object;
- include symlink-followed cases where both interfaces resolve to the same target;
- preserve lstat-style no-follow identity for the symlink object itself when requested;
- avoid path-, apk-, fd-, library-, or payload-specific cases;
- keep metadata derived from the authoritative namespace rather than creating a second metadata truth;
- add focused permanent regression coverage proving equality of `(st_dev, st_ino)` for the same object across open+fstat and newfstatat;
- retain deterministic errno behavior and checked copyout.

The review finding and attribution are recorded in:

- `docs/research/AGENT_FRAMEWORK_FAILURE_LEDGER.md`
- `docs/research/agent-framework-failure-ledger.jsonl`

FILE-BACKED MMAP(222) IMPLEMENTATION REQUIREMENTS

Implement the smallest bounded general mechanism justified by the observed requests.

Required properties:

1. Resolve the descriptor through the existing binding/resource ownership model.
2. Accept only resource classes actually coherent for file-backed mapping.
3. Validate page alignment and checked address/length/offset arithmetic.
4. Validate requested file range against the authoritative resource bytes.
5. Preserve MAP_PRIVATE semantics: mapped bytes are private to the process mapping and writes must not mutate the immutable namespace source.
6. Preflight mapping-table capacity, address-space occupancy, page backing, and all other bounded resources before commitment where practical.
7. Preserve PREPARE -> COMMIT discipline and rollback on partial failure.
8. Preserve W+X=0. Do not create writable+executable mappings.
9. Respect requested R/W/X permissions rather than mapping every file RWX or RW.
10. Preserve SUM clear and existing trap/memory safety invariants.
11. Do not mutate file offset as a side effect of mmap.
12. Preserve descriptor/resource ownership and reference accounting.
13. Zero-fill the tail of the final page beyond available mapped file bytes when required by the bounded mapping shape.
14. Return deterministic Linux-compatible errno for invalid fd, unsupported mapping class, bad range/alignment, capacity exhaustion, and mapping failure.
15. No special cases for apk, libcrypto, libapk, fd 3, or any named path.
