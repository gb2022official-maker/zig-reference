KNOWN CHECKPOINT

PR #96 intentionally landed the Batch 32S file-backed MAP_PRIVATE work to advance the project while preserving two known semantic defects for this fresh run.

Known defect A — whole pages beyond EOF:

The current planner computes byte_length = min(length, file_size - offset) while retaining mapped_length rounded from the full requested length. As a result, a request that extends by one or more complete pages past EOF can install readable zero-backed pages wholly beyond the file. Linux does not make those pages ordinary readable file contents. Because Morphic does not yet have a SIGBUS/page-fault path for this mapping class, this slice must choose the smallest correct bounded behavior: reject such mappings before mutation or leave wholly-beyond-EOF pages inaccessible, with focused permanent proof.

Known defect B — unsupported protection shapes:

The current planner accepts PROT_NONE and write-only protection even though the Sv39 leaf path cannot directly encode those shapes as currently wired. That can turn an accepted request into a later mapping failure and misleading ENOMEM-style behavior. The compatibility edge must handle these combinations deliberately. Use the smallest general policy consistent with Linux-visible behavior and current Morphic mechanisms. Do not silently accept a protection shape that the mapping layer cannot represent.
